# WPA2 4‑Way Handshake Analysis

*A beginner‑friendly research explanation*


## Introduction

In this section of the project I explain how WPA2 authentication works
in a real wireless network.
The focus is the **4‑Way Handshake**, which is the mechanism used by 
WPA2‑Personal networks to securely derive encryption keys and set-up a connnection between a
wireless client and an access point.

# Parties Involved in WPA2 Authentication

Before explaining the handshake itself, we should first understand **who
is involved** in the communication.

In a normal wireless network there are two main actors.

### 1. The Access Point (AP) 

The **Access Point** is the wireless router that provides the Wi‑Fi
network.

Responsibilities of the AP include: broadcasting the wireless network name (SSID) and authenticating devices that want to join the network

### 2. The Client

The **client** is any device attempting to connect to the wireless
network.

Examples include: laptops , phones ,tablets , IoT devices

The client must prove that it knows the correct Wi‑Fi password before
the access point will allow it to communicate on the network.

# WPA2 Personal vs WPA2 Enterprise

Before discussing the handshake we also need to understand that WPA2 has
two different authentication modes.

### WPA2‑Personal

WPA2‑Personal uses a **Pre‑Shared Key (PSK)**.
This means:
-   every device connecting to the network uses the **same password**
-   the password is shared among users of the network

### WPA2‑Enterprise
WPA2‑Enterprise is used in larger environments.

Instead of a shared password, authentication is handled by a **central
authentication server** such as a RADIUS server.

Each user typically has:
-   unique individual username and password 
-   sometimes certificates

Enterprise authentication is more scalable but also more complex to
deploy. for more information click [here](https://www.tp-link.com/en/support/faq/500/)


# What is a Pre‑Shared Key (PSK)?

A **Pre‑Shared Key** is simply the Wi‑Fi password configured on a
router.
Example:
    SSID: schoolwifi , Password:password123

However, WPA2 does **not directly use this password for encryption**.

Instead, the password is processed through a cryptographic algorithm to
produce a stronger key.

This derived value is called the **Pairwise Master Key (PMK)**.

The PMK is generated using a key derivation function that combines:

-   the Wi‑Fi password
-   the network SSID

Once both the client and the access point know the PMK, they can begin
the authentication process that derives temporary session keys.

This is where the **4‑Way Handshake** begins.


# Purpose of the 4‑Way Handshake

The 4‑Way Handshake has one main goal:

**to prove that both the client and the access point know the same PSK
without transmitting the password across the network.**

At the same time the handshake also:

-   generates fresh encryption keys
-   prevents replay attacks
-   establishes secure communication parameters


# Key Concepts Used in the Handshake

Before looking at the steps, it helps to understand the main
cryptographic elements involved.


## Nonces

A **nonce** is a random number used once.
In WPA2 there are two important nonces.

### ANonce

Generated by the access point.
Used to help create session keys.


### SNonce

Generated by the client.
Also used during the key derivation process.


The presence of these random values ensures that **each authentication
session produces unique encryption keys**, even if the same password is
reused.


## PTK (Pairwise Transient Key)

The **Pairwise Transient Key** is the encryption key used for secure
communication between the client and the access point.

It is derived from several inputs:

-   Pairwise Master Key
-   ANonce
-   SNonce
-   MAC address of the client
-   MAC address of the access point

Because these values change per session, the PTK is unique for every
connection.


## GTK (Group Temporal Key)

The **Group Temporal Key** is used for **broadcast and multicast
traffic**.

For example:
-   ARP broadcasts
-   network announcements

The access point distributes the GTK to clients during the handshake. GTK is the key that all clients share for broadcast/multicast messages, so they can read these ARP messages/anouncements safely.


## MIC (Message Integrity Code)

The **Message Integrity Code** ensures that handshake messages are not
altered during transmission.

It provides:
-   integrity
-   authentication of handshake messages

If a message is modified, the MIC validation will fail and the
authentication process will stop.


# The 4‑Way Handshake Process
Now we can look at the handshake itself. The handshake occurs immediately after a device attempts to join the network.

## Message 1

Access Point → Client

The access point sends the **ANonce** to the client.
Purpose:
-   initiate the key generation process

## Message 2
Client → Access Point

The client generates:
-   SNonce
-   PTK

The client then sends:
-   SNonce
-   Message Integrity Code

This proves that the client possesses the correct PMK derived from the
password.

## Message 3
Access Point → Client

The access point now performs the same PTK calculation.

If the MIC matches, the AP knows the client is legitimate.

The AP then sends:
-   the Group Temporal Key (GTK)
-   encryption parameters


## Message 4
Client → Access Point

The client sends a final confirmation message.
At this point both sides possess:
-   PTK for secure unicast communication
-   GTK for broadcast traffic

The wireless session is now encrypted and normal network traffic can
begin.

# Brief Note on Offline Password Attacks

While the WPA2 handshake is secure by design, it introduces an
interesting security property.

If an attacker captures the handshake packets, they may attempt to**guess the password offline** by testing password candidates against the captured handshake data by using various exploitation tools such as hashcat or aircrack-ng these tools attempt to recreate substrantial information such as the PMK OR GTK
